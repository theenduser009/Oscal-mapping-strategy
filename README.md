Yes — you want the distinct parent element types and the distinct child element types from the SSP relationships.

Use this:

SELECT DISTINCT
    p.ELEMENT_TYPE AS PARENT_ELEMENT_TYPE,
    c.ELEMENT_TYPE AS CHILD_ELEMENT_TYPE
FROM RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.FACT_OSCAL_SSP_DEPENDENCY f

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT p
    ON f.FK_SOURCE_ELEMENT_HASH = p.PK_OSCAL_SSP_ELEMENT_HASH

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT c
    ON f.FK_TARGET_ELEMENT_HASH = c.PK_OSCAL_SSP_ELEMENT_HASH

ORDER BY
    PARENT_ELEMENT_TYPE,
    CHILD_ELEMENT_TYPE;

That gives you the unique relationship pairs, for example:

system-security-plan   metadata
system-security-plan   system-characteristics
metadata               responsible-parties
system-characteristics props
system-implementation  components

If you want just distinct parents:

SELECT DISTINCT
    p.ELEMENT_TYPE AS PARENT_ELEMENT_TYPE
FROM RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.FACT_OSCAL_SSP_DEPENDENCY f
JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT p
    ON f.FK_SOURCE_ELEMENT_HASH = p.PK_OSCAL_SSP_ELEMENT_HASH
ORDER BY 1;

And just distinct children:

SELECT DISTINCT
    c.ELEMENT_TYPE AS CHILD_ELEMENT_TYPE
FROM RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.FACT_OSCAL_SSP_DEPENDENCY f
JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT c
    ON f.FK_TARGET_ELEMENT_HASH = c.PK_OSCAL_SSP_ELEMENT_HASH
ORDER BY 1;

The first query is the one I’d run because it shows the actual parent → child structure.
