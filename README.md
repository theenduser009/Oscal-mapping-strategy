Yes. If you mean distinct child element types under system-implementation, plus their METADATA_JSON, use:

SELECT DISTINCT
    c.ELEMENT_TYPE AS CHILD_ELEMENT_TYPE,
    c.METADATA_JSON AS CHILD_METADATA_JSON
FROM RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.FACT_OSCAL_SSP_DEPENDENCY f

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT p
    ON f.FK_SOURCE_ELEMENT_HASH = p.PK_OSCAL_SSP_ELEMENT_HASH

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT c
    ON f.FK_TARGET_ELEMENT_HASH = c.PK_OSCAL_SSP_ELEMENT_HASH

WHERE p.ELEMENT_TYPE = 'system-implementation'
  AND p.SOURCE_RECORD_ID = '5193'

ORDER BY CHILD_ELEMENT_TYPE;

But one important detail: DISTINCT applies to both columns together. So if components has many different JSON payloads, you'll still get multiple components rows.

If you want literally one row per distinct child type, use this instead:

SELECT
    c.ELEMENT_TYPE AS CHILD_ELEMENT_TYPE,
    ANY_VALUE(c.METADATA_JSON) AS SAMPLE_METADATA_JSON,
    COUNT(*) AS CHILD_COUNT
FROM RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.FACT_OSCAL_SSP_DEPENDENCY f

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT p
    ON f.FK_SOURCE_ELEMENT_HASH = p.PK_OSCAL_SSP_ELEMENT_HASH

JOIN RTX_ENTERPRISESERVICES_DEV.ES_ESC_GRC_CURATED.DIM_OSCAL_SSP_ELEMENT c
    ON f.FK_TARGET_ELEMENT_HASH = c.PK_OSCAL_SSP_ELEMENT_HASH

WHERE p.ELEMENT_TYPE = 'system-implementation'
  AND p.SOURCE_RECORD_ID = '5193'

GROUP BY c.ELEMENT_TYPE
ORDER BY c.ELEMENT_TYPE;

That second one is probably what you want for understanding the OSCAL structure: child type + one sample payload + how many instances of that child exist.
